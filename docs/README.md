## 왜 사본을 두나

원본은 docx · xlsx, 즉 zip 압축 파일이다. `grep` 도 `git diff` 도 통하지 않는다.
요구사항을 코드와 나란히 검색하고("`INB-003` 이 뭐였지"), 개정 내용을 커밋 이력으로
따라가려면 평문 사본이 있어야 한다.

## 고칠 때

**사본을 직접 고치지 않는다.** 원본을 고치고 저장소 루트에서 다시 만든다.

```bash
node docs/tools/ooxml-to-md.mjs
```

스크립트가 변환 후 건수를 원본이 선언한 값(기능 98 · 프로그램 115)과 대조해,
어긋나면 경고한다. 손으로 고치면 이 대조가 무의미해지고 원본과 조용히 갈라진다.

압축 해제에 PowerShell 의 `Expand-Archive` 를 쓰므로 Windows 를 전제한다.

## 현재 구현과 문서 사이의 알려진 차이

문서를 읽고 대조하면서 확인된 차이다. **해결된 것은 지우지 말고 해결 내용을
남긴다** — 전에 이 표에 "tb_org 가 요구사항의 4계층과 다르다"고 적어 두고도
그대로 기준정보를 착수해, 나중에 회사·조직·플랜트를 전부 다시 만들어야 했다.

| # | 차이 | 상태 |
| --- | --- | --- |
| 1 | 시드에 오프라인 매장이 들어 있었다 (요구사항 1.2 범위 외) | **해결** — 조직·역할·권한·정책·코드에서 모두 제거 |
| 2 | `tb_org` 이 본사/센터/매장 평면 구조여서 요구사항의 회사 → 물류센터 → 창고타입 → 로케이션 4계층과 달랐다 | **해결** — `tb_company`·`tb_org`·`tb_plant`·`tb_warehouse`·`tb_location` 5계층으로 분리 (MST-PG-001~003) |
| 3 | 구현한 공통정책이 프로그램 목록의 COM-PG-007 정의와 다를 수 있다 | **미해결** — 목록은 "업무별 승인 기준 및 임계값", 구현은 역할별 제한·승인 규칙. AUTH-008 + MST-013 에 더 가깝다 |
| 4 | 프로그램 목록의 진행상태가 코드와 어긋난다 | **미해결** — 엑셀 진척표를 갱신해야 한다 |
| 5 | 인터페이스(INT-* 10건) 전량 취소라 주문 유입 경로가 비어 있다 | **미해결** — ORD 단계는 OMS 수신(IFR-OMS-01)을 전제하는데 그 프로그램이 범위에서 빠졌다 |
| 6 | 요구사항 1.6 의 도메인 코드 체계가 두 줄로 서로 다르게 적혀 있다 | **미해결** — 첫 줄 `AUTH/CMN/MST/STK/…`, 둘째 줄 `COM/MST/LOC/CHN/STK/…` |
| 7 | 재고(4차)가 플랜트를 비정규화해서 들고 있어야 하는가 | **결정 필요** — 로케이션만 참조하면 정규형이지만 플랜트별 재고 조회에 조인이 3개 붙는다 |
