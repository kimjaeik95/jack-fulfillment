## 1. 문서 개요

### 1.1 목적
패션 의류 유통물류 온라인 판매를 대상으로 하는 창고관리시스템(WMS)의 기능 · 비기능 · 인터페이스 · 데이터 요구사항을 정의하고, 설계 · 개발 · 테스트 단계에서 추적 가능한 기준을 확립한다.

### 1.2 시스템 범위
| 구분 | 내용 |
| --- | --- |
| 포함 (자체 구축) | 재고 · 로케이션 관리, 입고(예정 · 검수 · 적치), 재고 할당, 출고(지시 · 피킹 · 패킹), 실사 · 조정, 구매요청 · 구매오더, 판매오더(B2B · B2C), 채널 SKU 매핑, 조회 · 집계 |
| 제외 (외부 솔루션) | OMS — 채널 주문 수집 · 주문 정규화 · CS · 취소 · 반품 접수 / 택배시스템 — 송장번호 발번 · 집화 · 배송 추적 · 배송완료 회신 |
| 제외 (범위 외) | 오프라인 매장 운영 전반 — 매장 기준정보 · 매장재고 · 매장간 재고이동 · 매장↔물류센터 보충(Pull/Push) · POS 판매 |


### 1.3 대상 업무 특성
- 패션 의류 — 색상 × 사이즈 조합으로 SKU 폭증 (제품 1건에 SKU 20~40건), 시즌 속성 필요
- 멀티채널 — 자사몰 · 오픈마켓(쿠팡 · 무신사 등) 주문 수집 전제, 채널별 외부 상품코드 상이
- 모든 트랜잭션은 제품이 아니라 SKU를 FK로 참조한다
- 재고는 반드시 '어떤 장소의 어떤 빈'에 존재한다 (재고 키 = 빈 × 상품코드 × 거래처)

### 1.4 핵심 원칙 (설계 제약)
아래 6개 원칙은 전체 요구사항이 전제하는 설계 제약이다. 개발 착수 전 확정되어야 하며, 변경 시 다수 요구사항이 영향을 받는다.
| ID | 원칙 |
| --- | --- |
| P-01 | 판매가능수량 = 실제 보유수량 − 할당수량. 판매가능수량은 주문 할당 시점에, 실제 보유수량은 출고 확정 시점에 차감한다. |
| P-02 | 재고(Stock)는 현재 상태(UPDATE), 재고할당이력 · 재고이력은 기록(INSERT). 스냅샷과 로그를 혼용하지 않는다. |
| P-03 | 재고 수량의 정본(Source of Truth)은 재고 테이블이며, 빈 수량은 집계 · 캐시용으로만 사용한다. |
| P-04 | 수량을 변경한 모든 행위는 사유코드 · 시점 · 대조수량 3종을 남긴다. 이것이 없으면 원인을 설명할 수 없다. |
| P-05 | 가격은 시점 스냅샷으로 트랜잭션에 복사 저장한다 (제품 단가 · 채널 판매가 · 판매오더 단가 상이). |
| P-06 | 수량 체인(요청 → 승인 → 지시 → 할당 → 피킹 → 패킹 → 출고 / 예정 → 기입고 → 정상입고)의 구간별 차이가 곧 문제의 위치다. 각 구간 수량을 보존한다. |


### 1.5 용어 정의
| 용어 | 정의 |
| --- | --- |
| SKU | 색상 · 사이즈 등 옵션까지 특정된 재고 관리 최소 단위 (옵션코드) |
| 빈 / 로케이션 | 재고가 실제로 놓이는 최소 주소 단위. 창고타입 하위의 섹터 + 구역 + 층 |
| 창고타입 | 한 물류센터 내의 물리 구획 · 용도 구분 (양품 · 반품 · 불량) |
| 온라인 매장 / 채널 | 자사몰 · 오픈마켓 등 세일즈 채널. 채널재고(Channel Stock)를 보유한다 |
| 기입고수량 | 해당 입고상세 라인에 대해 지금까지 누적 입고된 수량 (부분입고 합계) |
| 단포 / 합포 | 주문 1건 = 박스 1개  /  여러 주문상세 · 여러 주문 = 박스 1개 |

### 1.7 우선순위 기준

| --- | --- |

## 2. 기능 요구사항
도메인 정리 자료의 섹터 구분을 따르며 개발 단계 순서로 배열되어 있다. '인수 기준'은 해당 요구사항의 개발 완료를 판정하는 근거이며, 관찰 가능한 결과로 기술한다.

## 6. 개발 진행 권고 (요청 단위)

### 6.1 0단계 — 공통 규약 선행 확정
기능 개발에 앞서 아래 항목을 하나의 문서로 확정한다. 이것이 없으면 단계를 나눠 개발할 때 네이밍 · 상태값 · 예외 처리가 단계마다 달라진다.
- 전체 스키마 (확정 가능한 범위까지의 DDL)
- 레이어 구조와 폴더 규칙
- 상태값 enum 정의 (본 문서의 상태 전이 기준)
- 에러 처리 · 응답 포맷 · 트랜잭션 경계 규칙
- 수량 증감 처리 규칙 (P-01 ~ P-06 구현 방식)

### 6.2 단계별 진행 순서
1단계부터 12단계 순서로 진행한다. 뒤쪽 단계가 앞쪽 단계의 결정 위에 얹히므로 순서를 건너뛰지 않는다.
- 특히 4단계(재고관리)를 확정하기 전에 6단계(입고) · 8단계(할당) · 9단계(출고)를 만들면, 재고 갱신 방식 변경 시 전면 재작업이 발생한다.
- 한 단계가 너무 크면 세로 슬라이스 대신 레이어로 쪼갠다 : 테이블 · 리포지토리 → 서비스 로직 → API → 화면.
- 1차 오픈 범위는 우선순위 M 58건이다. S 39건 · C 4건은 2차 이후로 배치한다.
